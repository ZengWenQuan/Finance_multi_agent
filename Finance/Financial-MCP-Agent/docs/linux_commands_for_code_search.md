# Coding Agent 常用 Linux 命令说明

## 1. 为什么要了解这些命令

像 Codex、Claude Code 这类 coding agent，在搜索代码、定位函数、追踪调用链时，底层经常依赖一组非常朴素但非常高效的 Linux / Unix 风格命令。

这些命令通常负责几类事情：

- 找文件
- 搜文件内容
- 读取局部上下文
- 看目录结构
- 追踪符号和调用关系

也就是说，agent 的“抓取上下文”并不是一个神秘黑盒，很多时候就是：

- 先用搜索命令召回候选位置
- 再用读取命令抓取局部上下文
- 最后再做分析

---

## 2. 最常用的几类命令

可以把这些命令分成下面几类：

1. 文件定位命令
2. 文本搜索命令
3. 上下文读取命令
4. 目录查看命令
5. 调用链辅助命令

---

## 3. 文件定位命令

这类命令的作用是：

**先找到可能相关的文件。**

## 3.1 `rg --files`

### 作用

快速列出仓库中的文件列表。

### 常见用法

```bash
rg --files
rg --files | rg "match"
```

### 它能做什么

- 列出所有文件
- 再按文件名过滤
- 快速找模块、目录、测试文件、配置文件

### 为什么常用

因为它通常比 `find` 更快，而且非常适合配合 `rg` 二次筛选。

### 在 agent 里的用途

当 agent 想知道：

- 有没有文件名带 `match`
- 有没有 `service`、`controller`、`router`
- 有没有测试文件

它常会先用这个命令。

---

## 3.2 `find`

### 作用

按路径、文件名、类型等条件查找文件。

### 常见用法

```bash
find . -iname "*match*"
find . -type f -name "*.py"
find . -type d -name "src"
```

### 它能做什么

- 按文件名匹配
- 按扩展名查找
- 按目录类型查找
- 做更复杂的文件筛选

### 在 agent 里的用途

当 agent 想更精细地限定搜索范围时，会用 `find`。

例如：

- 只找 Python 文件
- 只找某个目录下的文件
- 只找目录，不找普通文件

---

## 4. 文本搜索命令

这类命令的作用是：

**在文件内容里搜索关键词、函数名、字段名、报错信息。**

这通常是 agent 最重要的一类命令。

## 4.1 `rg`

### 作用

`rg` 是 `ripgrep`，用来在文件内容里快速搜索文本。

### 常见用法

```bash
rg "match"
rg -n "match" .
rg -n "compare|score|rank" src
rg "select_best_candidate"
```

### 参数说明

- `-n`：显示行号
- `.`：在当前目录递归搜索
- `src`：只在 `src` 目录搜索

### 它能做什么

- 搜函数名
- 搜类名
- 搜字段名
- 搜注释
- 搜日志
- 搜报错文案

### 为什么比 `grep` 常用

因为它：

- 更快
- 默认递归搜索
- 默认忽略很多无关文件
- 更适合大代码仓库

### 在 agent 里的用途

如果用户说：

- “找匹配函数”
- “找登录逻辑”
- “找上传入口”

agent 通常第一反应就是用 `rg` 搜关键词。

---

## 4.2 `grep`

### 作用

经典文本搜索命令，用来匹配文件内容。

### 常见用法

```bash
grep -R "match" .
grep -Rn "match" src
```

### 参数说明

- `-R`：递归搜索
- `-n`：显示行号

### 它能做什么

和 `rg` 类似，也能搜索：

- 关键词
- 函数名
- 类名
- 字段

### 为什么现在很多 agent 更偏 `rg`

`grep` 能做的事 `rg` 基本都能做，而且 `rg` 在大多数代码库里更快、更适合开发搜索。

### 在 agent 里的用途

如果环境里没有 `rg`，常见回退方案就是 `grep`。

---

## 5. 上下文读取命令

这类命令最关键，因为它们负责：

**把命中的局部代码上下文抓出来给 agent 看。**

这就是你说的“抓取上下文”的核心命令。

## 5.1 `sed`

### 作用

按行号读取文件的某一段内容。

### 常见用法

```bash
sed -n '120,180p' app.py
sed -n '1,200p' src/services/matcher.py
```

### 参数说明

- `-n`：不自动打印全部内容
- `'120,180p'`：只打印 120 到 180 行

### 它能做什么

- 读命中行附近几十行
- 看函数定义上下文
- 看某段逻辑前后关系

### 为什么很重要

搜索命令只能告诉 agent：

- 哪一行命中了

但 `sed` 才能告诉 agent：

- 这个命中周围的函数是什么
- 参数是什么
- 上下文里还调用了谁
- 它到底是不是目标逻辑

### 在 agent 里的用途

这通常是最典型的“抓取上下文”命令之一。

---

## 5.2 `cat`

### 作用

直接输出整个文件内容。

### 常见用法

```bash
cat app.py
cat requirements.txt
```

### 它能做什么

- 读小文件
- 读配置文件
- 读脚本文件

### 局限

如果文件很大，直接 `cat` 整个文件通常不合适。

### 在 agent 里的用途

更适合：

- 小文件
- 配置文件
- 入口脚本

对于大文件，agent 往往更偏向 `sed` 这种局部读取。

---

## 5.3 `head`

### 作用

读取文件开头部分。

### 常见用法

```bash
head app.py
head -n 50 app.py
```

### 它能做什么

- 看文件开头导入
- 看 shebang
- 看开头定义

### 在 agent 里的用途

适合快速判断：

- 这个文件是干什么的
- 有没有主入口
- 依赖了哪些模块

---

## 5.4 `tail`

### 作用

读取文件末尾部分。

### 常见用法

```bash
tail app.py
tail -n 50 app.py
```

### 它能做什么

- 看文件末尾逻辑
- 看日志尾部
- 看程序结束处

### 在 agent 里的用途

当 agent 怀疑：

- 文件末尾有启动逻辑
- 日志里有报错

就会用 `tail`。

---

## 6. 目录查看命令

这类命令的作用是：

**理解项目结构。**

## 6.1 `ls`

### 作用

列出目录内容。

### 常见用法

```bash
ls
ls -la
ls src
```

### 参数说明

- `-l`：详细列表
- `-a`：显示隐藏文件

### 它能做什么

- 看目录结构
- 看有哪些文件
- 看隐藏配置文件

### 在 agent 里的用途

agent 常会先看：

- 根目录下有什么
- 有没有 `src`、`app`、`test`、`docs`
- 有没有配置文件如 `.env`、`.gitignore`

---

## 6.2 `tree`

### 作用

以树状方式展示目录结构。

### 常见用法

```bash
tree
tree src
tree -L 2
```

### 参数说明

- `-L 2`：只展示两层深度

### 它能做什么

- 一眼看出模块层级
- 看目录之间的组织方式

### 在 agent 里的用途

非常适合快速建立项目地图。

不过有些环境不一定安装了 `tree`，这时 agent 会用 `ls` 或 `find` 替代。

---

## 7. 调用链辅助命令

这类命令的作用是：

**帮助 agent 从一个定义继续追调用关系。**

## 7.1 再次用 `rg` 搜函数名

虽然看起来它只是搜索命令，但在代码搜索中它也经常被拿来做“调用链跟踪”。

例如：

```bash
rg "select_best_candidate"
```

### 它能做什么

- 找定义
- 找调用点
- 找测试
- 找注释说明

### 在 agent 里的用途

这是最常见的调用链追踪方式之一。

很多时候，agent 根本不是依赖复杂静态分析器，而是直接：

- 搜函数名
- 看定义
- 看谁调用它
- 再继续搜下一层函数名

---

## 7.2 `wc`

### 作用

统计行数、字数、字符数。

### 常见用法

```bash
wc -l app.py
```

### 它能做什么

- 看文件有多大
- 判断是否适合整体读取

### 在 agent 里的用途

帮助决定：

- 是直接读整个文件
- 还是只读局部片段

---

## 8. 什么命令最像“抓取上下文”

如果专门回答“哪些命令是在抓取上下文”，最核心的是这几个：

### `sed`

最典型。

因为它能按行号读取局部代码片段。

### `cat`

适合小文件或配置文件的整体上下文读取。

### `head`

抓文件开头上下文。

### `tail`

抓文件结尾或日志上下文。

### `rg -n`

虽然它主要是搜索命中位置，但因为它带行号，实际上也是上下文抓取的起点。

真正常见流程是：

1. `rg -n "关键词"` 先找到命中行
2. 再用 `sed -n '起始行,结束行p' 文件名` 读附近上下文

这就是最典型的：

**搜索 + 抓上下文**

---

## 9. 一个典型组合流程

假设 agent 想找“匹配功能函数”。

它可能会这样操作：

### 第一步：找可能相关文件

```bash
rg --files | rg "match|matcher|matching"
```

### 第二步：搜内容

```bash
rg -n "match|compare|score|rank" src
```

### 第三步：抓局部上下文

```bash
sed -n '120,180p' src/services/order_matcher.py
```

### 第四步：继续追下一级函数

```bash
rg "select_best_candidate"
rg "calculate_similarity_score"
```

### 第五步：必要时再读新位置的上下文

```bash
sed -n '40,120p' src/services/scoring.py
```

这就是一条非常典型的 coding agent 搜索链路。

---

## 10. 各命令一句话总结

- `rg --files`：列出文件，适合按文件名找候选
- `find`：按规则找文件和目录
- `rg`：最快最常用的内容搜索命令
- `grep`：经典内容搜索命令，常作回退方案
- `sed`：按行读取局部代码，是抓上下文核心工具
- `cat`：读整个小文件
- `head`：读文件开头
- `tail`：读文件结尾或日志尾部
- `ls`：看目录内容
- `tree`：看树状结构
- `wc -l`：看文件大小，辅助决定怎么读

---

## 11. 一句话总结

像 coding agent 这类系统，在代码搜索中最核心的命令组合通常是：

**`rg` 负责搜索命中位置，`sed` 负责抓取局部上下文，`rg --files` / `find` 负责找候选文件，`ls` / `tree` 负责理解目录结构。**
